# 30-Day Technical Founder Programme

## Principles

- The objective is technical founder agency, not becoming a career software engineer.
- AI coding agents are encouraged, but the founder must understand what is shipped.
- Every substantive feature should be inspected, tested and explainable.
- Important programme state belongs in files/Git rather than relying on chat context.

## Programme

**Day 1:** Git/GitHub foundations — repository, commit, staging, branches, remote, push/pull, PRs.

**Day 2:** How modern applications work — browser, frontend, backend, API, database, model, deployment.

**Day 3:** Program Extractor v0 — text input → LLM → structured JSON.

**Day 4:** Error handling — invalid inputs, API failure, malformed outputs, logs, HTTP status codes.

**Day 5:** Schemas and validation — Pydantic/structured outputs and deterministic validation.

**Day 6:** Deployment — environments, secrets, `.env`, frontend/backend deployment.

**Day 7:** Architecture review — understand every file, data flow, technical interrogation.

**Day 8:** University RAG begins — acquire and structure public university-programme data with provenance.

**Day 9:** Chunking, embeddings and pgvector/Supabase.

**Day 10:** Semantic retrieval without generation.

**Day 11:** Full RAG — retrieve evidence → grounded LLM response → citations.

**Day 12:** SQL/metadata filters + semantic search; understand hybrid retrieval.

**Day 13:** Evaluation — build known-answer test set and measure retrieval performance.

**Day 14:** Adversarial testing — missing, contradictory and outdated evidence; abstention.

**Day 15:** Deploy and document University RAG; scaling analysis.

**Day 16:** Cohort Engine begins — generate synthetic students and define feature schema.

**Day 17:** Deterministic hard-constraint pod allocation.

**Day 18:** Soft similarity scoring and baseline comparison.

**Day 19:** Add unit economics: seats, revenue, tutor costs, margin and pod viability.

**Day 20:** Simulate churn and dynamic state.

**Day 21:** Cohort rebalancing — merge, backfill and preserve continuity.

**Day 22:** Metrics — fill rate, viable pods, disruptions, margin and benchmark comparisons.

**Day 23:** Cohort Engine visual dashboard.

**Day 24:** Scale testing at 1k/10k/100k users where feasible; identify bottlenecks.

**Day 25:** Architecture and trade-off review of Cohort Engine.

**Day 26:** Founder Console begins — LLM + tools over synthetic product/GitHub data.

**Day 27:** Tool-calling loop and multi-step agent workflows.

**Day 28:** Agent guardrails, permissions, auditability and trust boundaries.

**Day 29:** GitHub portfolio polish — READMEs, diagrams, tests, CI, demos and pinned repos.

**Day 30:** Technical founder viva — explain systems without AI assistance and publish final retrospective.
